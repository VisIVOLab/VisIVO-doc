The switching rules
SWITCHPANES ARE FILLED WITHSIDE EFFECTS
▣ → ▥ Left keeps the current view. Right takes the first unused entry of 2D Slice → Moment 0 → Spectrum. Toolbar 3D/2D picker hides; per-pane title dropdowns appear. Linked enables, on by default, scope “camera · channel · LUT”.
▥ → ⊞ The two existing panes keep their slots (top-left, top-right). Bottom-left and bottom-right continue down the same list. Linked scope narrows to “channel · LUT”. Pane headers compact: padding 6/9, LUT strip 24 × 8, qualifier only if it fits.
⊞ → ▣ The active pane survives — the one with the filled dot — not always the first. Others hide; nothing is destroyed. Toolbar 3D/2D picker returns, set to whatever survived. Linked disables and dims, remembering its state for when you go back.
⊞ with 1 product If a slot has nothing to show, it renders an empty pane: dark background, a centred “Pick a view” dropdown, no border-chrome noise. Never leave a black rectangle with no explanation, and never silently fall back to 2 panes — the user asked for 4.
any, window < 1600 ▥ splits top/bottom instead of left/right — 1112 × 363 beats 552 × 735 for a channel map. ⊞ stays 2 × 2. The split direction is derived from window width, not remembered — resizing the window re-evaluates it.
Two invariants behind all of it. Nothing is created or destroyed by switching layout — every view is a widget that gets shown or hidden, so round-tripping ▣ → ⊞ → ▣ costs nothing and loses no camera, no zoom, no loaded slice. And the active pane is the unit of everything: which pane survives a downgrade, which one the channel scrubber drives, which one “Send slice to image viewer” takes. One filled dot in one header at a time, and clicking anywhere in a pane makes it active.
